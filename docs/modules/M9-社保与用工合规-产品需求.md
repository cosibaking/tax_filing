## 一、结论摘要

### 1.1 是否需要引入社保相关功能？

| 阶段 | 是否引入 | 范围 | 理由 |
|------|----------|------|------|
| **MVP（当前）** | ❌ 不引入完整模块 | 保持现有自查清单第 7 项 | 核心用户为一人 OPC，无雇员；税务闭环（增值税/企税）尚未完全跑通 |
| **Phase 2（近期）** | ✅ 引入轻量能力 | 社保咨询、灵活就业指引、清单智能跳过 | 主播高频问「要不要交社保」；进阶版套餐已承诺「社保代办」但当前无产品承载 |
| **Phase 3（中期）** | ✅ 引入用工台账 | 员工档案、工资录入、工资个税（F-42、F-57） | 社保申报的前置依赖；头部主播开始雇助理/剪辑 |
| **Phase 4（远期）** | ✅ 引入申报代办 | 社保公积金申报任务流（F-58） | 仅服务有真实雇员或选购增值包的客户；与各地社保系统对接成本高 |

**一句话：需要引入，但分阶段、分场景；MVP 不扩 scope，Phase 2 先做「咨询 + 指引」，完整申报能力排在 F-57 之后。**

### 1.2 与现有产品设计的关系

现有 PRD 已将社保定位为 **P4（F-58）**，并在自查清单（F-69）中以条件项出现（「有员工的话」）。该定位**基本正确**，本 PRD 补充两点：

1. **区分两类社保场景**，避免产品混为一谈：
   - **A 类：创始人/主播本人社保**（灵活就业 or 公司参保）—— 与 OPC 税务主线弱相关，但用户感知强
   - **B 类：雇员社保公积金申报** —— 仅在有真实劳动关系时适用，与 F-42/F-57/F-58 强相关

2. **进阶版套餐**（商业计划书）已含「社保/公积金代办」，需在 Phase 2 提供**可交付的工单流**，即使首期仍为顾问人工代办，也须在系统内留痕。

## 二、背景与问题定义

### 2.1 业务背景

| 驱动力 | 说明 |
|--------|------|
| 用户咨询高频 | 实操手册 Q3：「我当个体户/注册了公司，还要交社保吗？」 |
| 服务套餐缺口 | 进阶版（799–1999 元/月）含社保代办，系统无对应功能位 |
| 合规完整性 | 报税前自查清单含社保项，但无员工时顾问需人工勾选，体验差 |
| 客户结构演变 | 年入 100 万+ 主播常见雇 1–2 人（助理、剪辑），产生真实用工申报义务 |

### 2.2 目标用户与场景

| 用户 | 典型场景 | 产品诉求 |
|------|----------|----------|
| 纯个人 OPC 主播 | 无雇员，关心养老/医疗 | 了解灵活就业参保路径，**不强制走公司参保** |
| 有小团队的 OPC | 1–3 名雇员 | 工资入账、个税扣缴、社保申报提醒与代办 |
| 顾问/运营 | 进阶版客户 | 社保咨询工单、申报状态跟踪、材料归档 |
| MCN 签约主播 | 对公结算 + 助理团队 | 区分劳务外包 vs 劳动关系，合规指引 |

### 2.3 非目标（明确不做）

- ❌ MVP 阶段对接全国社保局统一 API（各地差异大、无稳定开放接口）
- ❌ 替用户承诺「不交社保也没事」类逃保话术
- ❌ 将创始人分红替代工资以规避社保的「方案设计」（合规底线 F-68 禁止）
- ❌ 与税务申报同等优先级的 P1 社保全自动申报

## 三、场景拆分：A 类 vs B 类

### 3.1 A 类 — 创始人/主播本人社保（咨询型）

**特征：**
- OPC 仅 1 名股东兼法人，无其他雇员
- 法律上：公司不为法人强制缴纳社保（各地实操有差异）
- 用户真实需求：养老、医疗连续性

**产品策略：**
- 提供**路径对比**（灵活就业 vs 公司参保 vs 城乡居民医保）
- 提供**属地化办事指引**（链接/步骤，非 API）
- 在诊断或 OPC 激活后**一次性推荐**，不进入申报任务流
- 可选：社保缴费测算计算器（按当地最低基数估算）

### 3.2 B 类 — 雇员社保公积金（申报型）

**特征：**
- OPC 存在真实劳动合同关系雇员
- 须按月：工资申报 → 个税扣缴 → 社保公积金申报
- 与 F-42、F-57、F-58 形成依赖链

**产品策略：**
- 员工档案 → 月度工资单 → 生成个税/社保任务 → 顾问代办标记完成
- 申报日历增加 `social_insurance`、`housing_fund` 任务类型
- 自查清单第 4、7 项与员工数据联动（无员工则自动 N/A）

## 五、用户旅程

### 5.1 A 类旅程（无雇员主播）

```
OPC 落地完成 → 系统询问「是否有雇员？」→ 选「无」
    → 展示「创始人社保指引」卡片（灵活就业推荐）
    → 可选「预约社保咨询」→ 顾问 4h 内回复
    → 报税前自查：第 4、7 项自动勾选 N/A
```

### 5.2 B 类旅程（有雇员 OPC）

```
OPC 落地 → 选「有雇员」→ 引导添加员工档案
    → 每月录入工资 → 自动生成工资个税任务（F-57）
    → 同步生成社保/公积金任务（F-58，Phase 4）
    → 顾问代办 → 回执存档 → 自查清单联动校验
```

### 5.3 顾问侧旅程

```
客户详情 → 用工状态标签（无雇员 / 有 N 人）
    → 社保咨询工单队列（Phase 2）
    → 申报工作台筛选 tax_type=social_insurance（Phase 4）
    → 批量标记已申报 + 上传回执
```

## 六、业务规则

### 6.1 用工状态判定

| 状态 | 条件 | 系统行为 |
|------|------|----------|
| `no_employee` | 用户确认无雇员，且无员工档案 | A 类指引；清单 4/7 项 N/A |
| `has_employee` | 存在至少 1 名在职员工档案 | 启用 B 类流程；清单 4/7 项必填 |
| `unknown` | 未填写 | OPC 激活后 7 日内弹窗催促填写 |

### 6.2 创始人社保合规话术（产品内置，不可编辑为逃保建议）

标准话术（源自实操手册 Q3）：

> 个体户/一人公司不强制为法人缴纳社保。若您全职从事直播经营，建议通过**灵活就业**或**城乡居民医保**等方式保持养老、医疗连续性。若您聘用员工，须依法为员工缴纳社保。

### 6.3 社保咨询工单 SLA

| 指标 | 承诺 |
|------|------|
| 首次响应 | 工作时间 4 小时内 |
| 办结 | 简单咨询 24h；涉及属地政策 3 工作日 |
| 留痕 | 咨询内容、顾问回复、附件全程审计 |

### 6.4 申报截止日（B 类，参考值，按属地配置）

| 险种 | 典型截止日 | 说明 |
|------|------------|------|
| 社保（五险） | 每月 15 日前申报缴纳上月 | 各地不同，系统用 `region_code` 配置 |
| 公积金 | 每月 25 日前 | 各地不同 |
| 工资个税 | 次月 15 日前 | 与自然人扣缴端一致 |

### 6.5 与自查清单联动（F-69 增强）

| Key | 原逻辑 | 增强逻辑 |
|-----|--------|----------|
| `payroll_tax` | 人工勾选 | `no_employee` → 自动 `checked` + `na: true` |
| `social_insurance` | 人工勾选 | 同上 |

## 附录 A：FAQ 内容草案

**Q：我当 OPC，还要交社保吗？**

一人 OPC 不强制为法人缴纳职工社保。建议根据您的实际情况选择：
1. **灵活就业参保**（推荐全职主播）：在户籍地或经营地按灵活就业人员身份缴纳养老、医疗；
2. **城乡居民医保**：适合已有居民医保且收入波动较大者；
3. **公司职工社保**：仅在有真实雇员时，为公司员工缴纳；法人本人参保需结合当地政策，请咨询顾问。

**Q：公司有员工，社保怎么报？**

需在每月申报期内完成：① 工资发放与入账；② 自然人扣缴端申报工资个税；③ 电子税务局或社保客户端申报五险；④ 公积金中心申报。选购进阶版可由顾问代办并上传回执。
